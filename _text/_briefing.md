## 一、赛务硬信息

### 1. 级别、时长、模块权重

- **级别：人工智能训练师二级（技师）**。佐证：同套题 B4 明写“你作为人工智能训练师二级人员，需为三级/高级工及以下级别人员开展……”。因此不是五级。
- **比赛作答总时长：240 分钟**。
  - **A 理论知识：90 分钟，100 分，权重 30%**（赛程 10:00–11:30）。
  - **B 技能操作：120 分钟，100 分，权重 50%**。
  - **C 综合评审：30 分钟，100 分，权重 20%**。
  - 现场 B+C 合并时段为 **14:00–16:30，共 150 分钟**。
- B 内部配分块：业务分析 25、智能训练 30、智能系统设计 40、培训与指导 5。指定题中：B1.1 为 25 分钟，B3 为 35 分钟；它们只是 B 模块的子题，不能把各自当成 B 总时长。

### 3. 入场与禁忌

- 必带本人身份证、参赛证；否则不得参赛。迟到超过开考 10 分钟不得入场：A 超过 10:10、B+C 超过 14:10，按弃权；开考后 30 分钟内不得提前离场。
- 必须独立作答；未经执裁人员许可，禁止与其他选手、赛务人员交流接触，违者取消资格。即**严禁他人代答/协作代答**。
- 严禁携带通讯工具（含手机）、智能穿戴、移动存储，以及书籍、纸张、笔等资料；不得接受场外传递物品或资料，违者取消资格。
- 题面未逐字写“禁止上网”，但竞赛是封闭、独立作答环境，且禁通讯工具及外部资料；**不得擅自联网求助、检索或传递答案**。如考机网络能力边界不清，须按现场指令，不可自行使用。
- 不得进入他人工位、干扰他人；不得在答案中加试题要求之外的标记；结束信号后必须立即停答。
- 饮水、去洗手间允许，但由赛务陪同且耗时计入比赛时间。
- 问题须举手，由非本单位执裁人员处理。

### 4. 与“五级标注员”的区别

- 本卷是**人工智能训练师二级（技师）**赛项：要求业务分析、数据/模型训练、多个智能产品的系统方案与实施、培训指导、综合产品设计；C 还要求把运营诉求转为功能需求、流程、JSON、伪代码和测试方案。
- “五级标注员”通常是入门级数据标注执行定位；但**本批文件未提供五级考试大纲或评分要求**，不能据此虚构其题型、时长、分值。备考上可确定的差异是：本卷明显不是只考按规范做单一标注，而是考“业务—模型—系统—实施—评审”的完整高级链路。

### 3. 10 道典型题与答案判断

> 原试题未给答案，以下全部为**【估计】**；判断依据为通行专业知识。

1. **判断**：去标识化后无法直接识别个人，因此可直接用于与用户原授权目的无关的新商业分析项目。  
   **答案：【估计】错。** 去标识化不等于可突破目的限制，仍需合法性基础、目的相容性及必要的授权/告知。
2. **判断**：PCA 是直接挑出方差最大的若干原始特征作为新特征集。  
   **答案：【估计】错。** PCA 构造原特征的线性组合，不是简单原特征筛选。
3. **判断**：L2 正则化主要使许多权重精确变为零。  
   **答案：【估计】错。** L2 倾向整体缩小权重；稀疏/精确归零更典型是 L1。
4. **单选**：第三方标注数据未经严格溯源，项目周期紧，最合规做法是什么？  
   **答案：【估计】C**：暂停使用，抽样验证和溯源调查，书面报告风险与延期可能。
5. **单选**：Excel 根据员工 ID 跨表返回薪资，最常用函数？  
   **答案：【估计】A：VLOOKUP / XLOOKUP。**
6. **单选**：标准跨职能泳道图中，菱形表示什么？  
   **答案：【估计】B：判断或决策节点。**
7. **单选**：Kanban 的核心实践之一是什么？  
   **答案：【估计】C：可视化流程并限制在制品 WIP。**
8. **多选**：属于集成学习的算法：随机森林、SVM、GBDT、AdaBoost。  
   **答案：【估计】A、C、D。**
9. **多选**：AI 模型特有攻击：对抗攻击、数据投毒、SQL 注入、模型窃取。  
   **答案：【估计】A、B、D。** SQL 注入是通用后端攻击。
10. **简答**：GBDT 训练集 99%、验证集 75%，列举五种兼含数据层和模型/算法层的缓解过拟合技术。  
    **参考答案：【估计】**①扩充/增强训练数据；②清洗噪声、处理泄漏并使用分层交叉验证；③降低树深/叶节点数；④增大叶节点最小样本数；⑤减小学习率并配合早停；亦可用 subsample/列采样、正则项。答题要写“措施＋为什么能提升泛化”，并明确至少一项数据层、一项模型层。

**简答高分公式**：先定义目标/问题 → 分层列措施 → 给指标与验证 → 给风险/闭环。避免只堆名词。

## 三、B1.1 餐饮行业智能点餐系统（25 分钟）

### 1. 场景与痛点

连锁快餐线上点餐：浏览菜单→选品→备注个性化需求→系统生成订单并推送门店→门店制作出餐→自取/配送。数据字段含订单编号、用户编号、下单时间、门店编号、商品明细、特殊备注、订单状态、出餐耗时。三大痛点：**转化/复购低、高峰拥堵与备注易错、门店接单和厨房调度低效/出餐延迟**。

### 2. 必交付物

- 业务框架：核心技术模块、系统—门店人员协作机制、数据输入/输出接口。
- 人机协同完整流程图：自动解析→人工校对→后厨→配送员，保证“少冰/去葱”等准确传递。
- 数据层、模型层优化方案。
- 针对三类痛点的具体优化：高峰流量调度、多轮点餐优化、门店协作效率提升。
- `桌面/参赛号/B1.1/答题卷.doc`，并录入平台最终提交。

### 3. 25 分钟步骤清单

1. **0–2 分钟：搭卷纲**：标题、业务框架表、流程图、数据/模型优化、三类痛点方案。
2. **2–7 分钟：框架**：输入层（菜单、订单、用户偏好、库存、门店产能、配送状态）→AI 层（NLP 备注解析、推荐/优惠、需求预测、智能调度）→业务层（下单、校对、后厨、配送）→输出（结构化备注、推荐结果、制作队列、预估出餐时间、告警）。补接口、权限、日志。
3. **7–14 分钟：人机协同图**：用户输入备注→NLP 抽取商品/属性/禁忌→置信度判断→低置信/冲突进入人工校对→确认结构化工单→库存/产能检查→后厨排队制作→完成→自取通知或分配配送员→送达/反馈。要有异常回路。
4. **14–18 分钟：数据/模型优化**：数据字典、标准词表、错别字/同义词、标注与质检、反馈回流；意图识别+槽位抽取、置信度阈值、离线准确率/召回率、线上错单率与A/B测试。
5. **18–23 分钟：三痛点方案**：推荐/优惠提高转化；限流、排队预估、多轮澄清改善高峰体验；按门店产能/库存/配送距离动态派单和厨房队列优化。
6. **23–25 分钟：校验保存**：三要素、两层优化、三个专项方案、人工兜底、图可读、路径/文件名、平台提交。

### 4. 评分点（按题面反推，非官方逐项分值）

- **框架合理可行**：模块齐全，技术和痛点对应；人、系统、后厨、配送边界清楚；输入输出可落地。
- **流程合理可行**：自动解析、置信判断、人工校对、后厨传递、配送安排均出现；判断分支与失败回路完整。
- **优化合理可行**：数据层和模型层均答；三个指定痛点逐一覆盖；有可量化指标（备注识别准确率、错单率、转化率、平均等待/出餐时长、准时率等）。
- 容易丢分：只画“用户→系统→门店”直线；无人工兜底；只写技术名词不写接口/输出；漏配送员；漏多轮点餐。

### 5. WPS/Office 建议图

用 **WPS 文字/Word 的形状＋连接符**画一张**横向泳道图**，泳道建议：用户｜智能点餐系统｜人工接单员｜后厨｜配送员。椭圆=开始/结束，矩形=处理，菱形=置信度/异常判断，文档/数据库图形=订单与日志。另用 4 层表格表示业务框架，速度比复杂架构图更稳。

## 四、B3 智慧物业全链路智能服务（35 分钟）

### 1. 场景

物业企业引入三个智能产品：**智能门禁、智能安防监控、智能报修与工单**，解决人工值守低效及安全隐患、监控只能人工回放无法实时预警、报修沟通低效且进度不透明。

### 2. 必交付物

1. 《智能产品功能匹配表》：三个产品各自“解决问题＋核心功能（含技术实现）”。
2. 三产品协同工作流程图。
3. 3 个核心目标，必须有可量化指标。
4. 4 阶段实施计划：总周期 **10 周**，含阶段名、周期、关键任务、责任人。
5. 员工抗拒新系统的 3 项应对措施。
6. 人力/物力/财力 3 类具体资源及到位验证方式。
7. 从“业主进小区”开始、**6 个以上关键操作节点**的全链路流程图。
8. 与传统流程比较：操作便捷性、信息实时性两方面具体优势。
9. `桌面/参赛号/B3/答题卷.doc`，并录入平台最终提交。

### 3. 35 分钟步骤清单

1. **0–7 分钟：功能匹配表**  
   - 门禁：人脸/二维码/车牌识别、权限库、陌生人告警、通行日志；
   - 安防：视频目标/行为检测、周界/烟火/跌倒等告警、联动录像；
   - 报修工单：App/小程序/NLP 分类、自动派单、SLA 计时、进度通知、回访评价。
2. **7–12 分钟：协同图**：门禁事件进入统一事件中心→异常触发安防复核→生成告警/工单→人员处置→结果回写三个系统与业主端。
3. **12–15 分钟：3 个量化目标**：例如通行验证时延、异常告警时延/召回率、报修响应与闭环时长；目标值可作为方案设定，但必须注明“建议目标”，不能伪称题面给定。
4. **15–21 分钟：10 周四阶段计划**：例：需求与勘察 1–2 周；方案/采购与数据准备 3–4 周；部署集成与试点 5–8 周；验收培训与推广 9–10 周。责任人写角色而非“相关人员”。
5. **21–25 分钟：变革和资源**：参与式需求访谈、分层培训+操作手册、试点标杆+激励/反馈；人力看人员名单/排班，物力看设备到货验收/台账，财力看预算批复/付款节点。
6. **25–31 分钟：全链路图（≥6 节点）**：业主到门口→身份识别→权限判断→放行并记日志→异常时安防抓拍/告警→事件中心研判→自动生成工单→派单→维修/安保处置→业主实时查看→验收评价→归档分析。
7. **31–35 分钟：传统对比＋检查保存提交**。

### 4. 评分点（按题面反推，非官方逐项分值）

- **解决方案合理可行**：三产品不孤立，技术实现具体，有统一身份/事件/工单/日志数据链。
- **实施推动合理可行**：恰为 4 阶段、总计 10 周；任务和责任人匹配；抗拒风险恰有 3 类措施；三类资源和验证证据齐全。
- **全链路设计合理可行**：从指定起点开始，节点≥6，有正常/异常分支、跨系统联动、闭环回写；便捷性和实时性对比具体。
- 易丢分：指标不可量化；四阶段周期相加不等于 10 周；只列资源不写验证；画三张孤立流程而非协同全链路。

- 图 1：**三系统协同泳道图**，泳道为门禁｜安防｜事件中台｜工单｜物业人员/业主。

## 五、C 综合评审：法律合同智能审查系统（30 分钟）

### 1. 场景与核心诉求

合同为 Word/PDF，人工审批与归档效率低、易漏未经授权付款、免责、隐含高风险、提前解除等条款，造成周期长和合规风险。输入示例为 JSON，含 `contract_id/title/parties/contract_type/clauses[{clause_id,content}]/timestamp`。三诉求：**实时识别高风险、动态更新规则库、保存标记结果用于审计追溯与统计**。

### 2. 要求文档结构（题面硬要求）

1. **需求转化：3 条标准化功能需求**  
   每条用：需求编号 `F-XX`；技术可实现且含配置能力的需求描述；至少 2 条可量化验收标准。分别覆盖：实时检测、关键字规则库管理、标记保存/后续审计。
2. **方案设计**  
   - 流程图：数据输入→文本预处理→高风险检测→人工审核→风险报告；
   - 判断点：是否含高风险？人工审核是否确认高风险？
   - JSON 规则模板：至少含 `keyword_list`、`enable_logging`；
   - 按不同维度统计风险合同并提供审计功能。
3. **实现规划**  
   - 高风险条款识别函数伪代码；
   - 高风险条款标记函数伪代码；
   - 验证方案：边界值、关键词覆盖、压力测试；每类均写测试类型、目标、数据示例、预期结果。
4. 保存：`桌面/参赛号/C/答题卷.doc`，录入平台并最终提交。

### 3. 评审要点（按题面与质量指标反推）

### 4. 建议答题卷纲要（直接套版）

#### 一、功能需求

- **F-01 实时高风险检测**：上传/接收 Word、PDF 或结构化合同后解析为条款，调用可配置风险类型、阈值/规则版本进行实时检测，返回命中条款、风险类型、级别、证据。验收写响应时间、召回/准确标准及指定样例命中结果。
- **F-02 关键字规则库管理**：管理员可新增、编辑、停用、查询、发布及回滚规则，配置关键词列表、风险类型、等级、生效时间、版本和日志开关。验收写发布生效时限、权限拦截、版本回滚成功率等。
- **F-03 标记、审计与统计**：保存命中及人工复核结果，支持按多维筛选、导出和追溯；日志不可缺字段。验收写查询时延、字段完整率、追溯成功率等。

> 具体性能目标值由考生作为方案值明确写出；题面未提供官方阈值，勿写成“题目规定”。

#### 二、系统方案

1. **流程图**：输入 Word/PDF/JSON→格式校验/OCR→分段清洗→规则/模型检测→“是否高风险？”→否：生成低风险报告；是：人工审核→“是否确认高风险？”→是：标记保存/告警/报告；否：改判并保存→审计归档→统计看板。人工结果回流规则优化。
2. **JSON 模板**（满足必填字段并扩展可维护性）：

```json
{
  "rule_id": "R-001",
  "risk_type": "提前解除权",
  "risk_level": "high",
  "keyword_list": ["随时解除合同", "无需承担违约责任"],
  "enable_logging": true,
  "enabled": true,
  "version": "1.0"
}
```

3. **统计与审计**：统计维度、指标（高风险合同数/率、风险类型分布、人工确认率、误报率、审核时长）、筛选导出；审计字段和权限控制。

#### 三、实现规划

1. **识别伪代码**：校验输入→预处理每条 clause→加载已启用规则和版本→匹配 keyword_list→形成 `{contract_id, clause_id, rule_id, hit_keyword, risk_level, evidence}`→返回候选风险。
2. **标记伪代码**：接收候选和审核结果→校验权限/状态→写风险标记→保存原文、证据、审核人、时间、规则版本→若 `enable_logging=true` 写审计日志→更新统计→返回成功/失败。
3. **测试矩阵**：
   - 边界值：空合同、0条/1条/超长条款、特殊字符；预期不崩溃、明确报错或正确处理。
   - 关键词覆盖：精确词、同义表达、大小写/空格、否定语境、多个词同时命中；预期命中正确并控制误报。
   - 压力：并发上传/批量合同、长文档；预期在所设响应时间、吞吐和错误率阈值内，日志/标记不丢失。
