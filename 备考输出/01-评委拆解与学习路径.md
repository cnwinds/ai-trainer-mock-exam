## 1. 整卷设计意图：为什么不是「五级标注员」

### 1.1 赛项定位（赛务手册原文能力）

赛务手册把项目定义为：用机器学习框架与算法优化工具，完成**数据预处理、模型训练与性能调优**，达到行业应用需求。技能要求覆盖：

1. **数据工程**：结构化数据集、清洗增强、数据质量评估；  
2. **模型开发与调优**：按场景选型（如 Transformer）、超参与结构优化；  
3. **工具链管理**：分布式训练平台（TensorFlow/PyTorch 集群等表述）。

这已超出「按规范做单一标注」的执行岗。

### 1.2 二级（技师）相对五级的能力跃迁（评委视角）

| 维度 | 五级标注员（典型定位，本批文件无五级大纲，仅作对照） | 本卷二级训练师实际考什么 |
|---|---|---|
| 工作对象 | 单条样本、标注规范 | 业务痛点→数据→模型→系统→实施→培训→产品化 |
| 交付形态 | 标注结果/质检表 | 框架图、流程图、ipynb/html、量化目标、伪代码、测试矩阵、培训计划 |
| 决策层级 | 执行「怎么标」 | 决定「做什么、怎么验收、怎么上线、怎么带人」 |
| 证据题 | — | B4 明文二级带三级；C 要求运营诉求→功能需求→设计→实现；B3 要求 10 周实施与变革管理 |

### 1.3 整卷命题逻辑（评委视角）

```
上午 A（30%）：知识广度 + 简答结构化表达（职业道德/法务/BPM/产品/ML/安全/项目管理/培训）
        ↓
下午 B（50%）：现场「做」——业务设计(B1) → 挖掘与方案(B1.2) → 训练数据工程(B2) → 多产品系统与落地(B3) → 带教(B4)
        ↓
     C（20%）：把运营诉求压成可验收产品规格（需求+流程+JSON+伪代码+三类测试）
```

**命题意图一句话**：考的是「能把 AI 嵌进业务并闭环落地的技师」，不是「会点标注工具的操作员」。权重上 **B 半壁江山、B3 系统设计 40 分是下午场胜负手**；A 的简答 40/100 决定理论能否拉开差距；C 是「产品化语言」压轴。

### 3.4 B2 股票指数训练集与测试（25 min）★ cnwinds 重点

**数据事实（素材）**：`B2.csv` **5400** 行；字段 `date,time,index_id,pct_change,sector,market_phase`；板块含医疗/教育/科技/能源/金融；阶段含牛市/熊市/震荡；日期约 2024-05-01～05-30；指数 ID 共 20 个。Notebook 已给 `pandas/scipy.stats/TimeSeriesSplit` 框架。

| 知识点 | 题面任务 | 评分关注点（估计） | 常见丢分 |
|---|---|---|---|
| 时间特征抽取 | 从 time 提取日期与小时 | 字段正确参与后续特征 | 只 parse 未用于聚合 |
| 特征① | 指数在每个时间段的平均涨跌幅 | groupby 逻辑正确并写入训练集 | 时间段定义含糊 |
| 特征② | 不同板块×市场阶段平均涨跌幅 | 交叉维度正确 | 只按板块或只按阶段 |
| 特征③ | 不同板块过去 5 个交易日涨跌趋势 | 滚动/移位按交易日；防泄漏 | 用未来数据；按行而非交易日 |
| 时序切分 | 按时间顺序划训/测；代表整体分布 | **禁止随机打乱** | `train_test_split` 随机切 |
| KS 偏差检测 | 测集板块/阶段涨跌幅 vs 整体 | 调用 KS、解读「是否一致」 | 只算不解释；维度漏阶段 |
| 热点板块测试方案 | 波动显著高于均值的板块：目标/方法/指标 | 完整三件套、可量化 | 写成买卖点/仓位策略 |
| 交付 | `B2.html` + `答题卷.doc` | 运行结果可见 | 只交源码无导出 |

**cnwinds 盘感迁移（允许） vs 禁止写法**

| 可借盘感（写进答题） | 禁止（会被看成跑题/风险） |
|---|---|
| 开盘/午盘/尾盘时段波动差异 → 定义「时间段」特征 | 「低吸高抛」「追涨停」「仓位 3 成」 |
| 板块轮动、牛熊震阶段分布不均 → 解释为何要 KS 与分层评估 | 「明日看多科技，目标点位…」 |
| 波动放大板块需单独压力测试 → 测试目标写稳定性/偏差 | 夏普、资金曲线当本题主指标（本题考数据与测试设计） |
| 评估指标：分板块准确率/MAE、校准度、KS 统计量、覆盖率 | 实盘回测年化收益当唯一成功标准 |

## 4. 下午场（B+C）评委真正在看什么

### 4.1 四条总标尺（评委视角）

1. **交付物完整性**：题面点名的表/图/三特征/html/伪代码/测试类，**缺一项即结构性失分**。  
2. **可量化**：目标、验收、评估指标必须带数字或明确度量（自拟值写「方案建议值」）。  
3. **闭环**：检测→人工→回写；训练→偏差检测→专项测试；实施→验证资源→评估培训。  
4. **可落地**：有接口/字段/责任人/周期/权限日志；不是概念海报。

### 4.2 得分句式（直接套用）

| 场景 | 得分句式 |
|---|---|
| 业务目标 | 「将【痛点】转化为指标【名称】，基线【X】，方案目标【Y】，验证方式【Z】。」 |
| 功能需求 | 「F-0X：系统应支持【可配置动作】；验收1：【指标】≤/≥【阈值】；验收2：【样例/权限】【结果】。」 |
| 人机协同 | 「当【置信度/规则】【条件】时走自动路径，否则进入【角色】人工【动作】，结果回写【系统/字段】。」 |
| 数据特征 | 「特征定义：【聚合键】上的【统计量】；窗口【N】；用途：刻画【业务现象】；注意【防泄漏】。」 |
| 测试方案 | 「测试目标：验证【稳定性/偏差】；方法：【分层/KS/压力】；指标：【分板块误差、覆盖率、p 值解读】。」 |
| 实施计划 | 「阶段【名】（第 a–b 周）：任务【…】；责任人【角色】；完成标志【可检查物】。」 |
| 培训 | 「关键点【唯一】；教法【讲练评】；掌握标准【能独立完成指标计算/评估表】。」 |

### 4.3 下午场时间盒（150 min，评委视角建议）

|---|---|---|
| 0–25 | B1.1 | 框架表+泳道图+数据/模型优化+三痛点方案 → 存 doc |
| 25–45 | B1.2 | 跑通三图+html；答题卷写价值与一场景方案 |

| 70–105 | B3 | 匹配表+协同图+3 目标+10 周四阶段+3 措施+资源验证+全链路+对比 |
